# CHANGELOG

## v2026.8.31

### Исправлено
- VK-канал снова загружается и запускается на OpenClaw 2026.8.1: после обновления gateway плагин больше не падает при старте из-за удалённых SDK entrypoints.
- Авторизация `pairing` продолжает работать отдельно для каждого VK-сообщества: запрос на подтверждение и ответ с кодом сохраняют правильный `accountId`, включая именованные аккаунты.
- Входящие вложения передаются в OpenClaw через актуальный ordered-media contract вместо устаревающих полей `MediaPath`, `MediaUrl` и их множественных вариантов.

### Сопровождение
- Минимальная поддерживаемая версия OpenClaw повышена до 2026.8.1 и явно объявлена в метаданных пакета, поэтому несовместимый gateway отклонит плагин до запуска.
- Проверка pull request теперь загружает собранный runtime на минимальной, актуальной стабильной и beta-версиях OpenClaw, а также запрещает удалённые, устаревающие SDK-imports и legacy media projection.

Кому важно:
- Пользователям, которые обновили OpenClaw до 2026.8.1 и увидели ошибку загрузки VK-плагина или остановку gateway до запуска канала.
- Пользователям нескольких VK-сообществ, где `pairing` должен храниться независимо для каждого аккаунта.
- Пользователям, которые отправляют изображения, документы и другие вложения во входящих сообщениях.

Что проверить после обновления:
1. Обновите плагин: `openclaw plugins install @openclaw-vk/vk@2026.8.31 --force --pin`.
2. Перезапустите gateway: `openclaw gateway restart`.
3. Выполните `openclaw plugins info vk --json` и `openclaw channels status --json --probe`; плагин должен загрузиться без ошибок SDK-import.
4. Отправьте личное сообщение от нового пользователя, получите код `pairing`, подтвердите его через `openclaw pairing approve vk <код>` и убедитесь, что бот отвечает.
5. Если подключено несколько VK-аккаунтов, повторите pairing для именованного аккаунта и убедитесь, что разрешение не открывает доступ к другому сообществу.
6. Отправьте сообщение с изображением и документом и убедитесь, что агент получает оба вложения в исходном порядке.

## v2026.6.19

### Добавлено
- Бот показывает ход работы реакциями-эмодзи прямо на вашем сообщении: 👍 принято → 🤔 думает → 👌 работает с инструментом → 🎉 готово (или 😡 при ошибке). Особенно полезно, когда ответ задерживается или обработка завершается без текста. Функция выключена по умолчанию — включается через `messages.statusReactions.enabled: true`; набор эмодзи и тайминги настраиваются в `messages.statusReactions`.

Кому важно:
- Пользователям VK, которые хотят сразу видеть, что бот принял сообщение и работает над ответом, даже если финальный ответ приходит не сразу или обработка падает без текста.

Что проверить после обновления:
1. Обновите плагин и перезапустите gateway: `openclaw plugins install @openclaw-vk/vk@2026.6.19 --force --pin`, затем `openclaw gateway restart`.
2. Включите реакции в `~/.openclaw/openclaw.json`: `messages.statusReactions.enabled: true`. Для личных сообщений также задайте `messages.ackReactionScope: "direct"` (или `"all"`) — иначе в личке реакции не появятся.
3. Напишите боту и убедитесь, что на вашем сообщении появляется и меняется реакция (👍 → 🤔 → 🎉).
4. Чтобы выключить — уберите `messages.statusReactions.enabled` или поставьте `false`: реакции полностью исчезают.

2. Перезапустите gateway: `openclaw gateway restart`.
3. Выполните `openclaw plugins info vk --json` и убедитесь, что плагин загружается без `TypeError`.
4. Выполните `openclaw channels status --probe` и отправьте тестовое сообщение в VK.

## v2026.5.5

### Исправлено
- Установка `@openclaw-vk/vk` через `openclaw plugins install` в свежих версиях OpenClaw больше не падает из-за отсутствующего compiled runtime output: опубликованный пакет теперь содержит собранные runtime entrypoints для канала VK и setup-мастера.
- При установке OpenClaw больше не предупреждает, что у VK-плагина нет статических metadata для конфигурации канала: пакет теперь объявляет базовый `channelConfigs.vk` в манифесте.

Кому важно:
- Пользователям, которые ставят VK-плагин как npm-пакет на OpenClaw 2026.5.x и видели ошибку про `expected ./dist/index.js` при установке.

Что проверить после обновления:
1. Установите новую версию пакета: `openclaw plugins install @openclaw-vk/vk@2026.5.5`.
2. Выполните `openclaw plugins info vk --json` и убедитесь, что плагин установлен и entrypoint указывает на `dist/index.js`.
3. Перезапустите gateway: `openclaw gateway restart`.
4. Отправьте тестовое сообщение в VK и проверьте, что канал отвечает без ошибок в логах gateway.

## v2026.4.4

### Добавлено
- Ответы с markdown-ссылками на локальные файлы и изображения теперь можно отправлять в VK как реальные вложения. Это касается и относительных путей внутри workspace, а не только публичных URL.
- В OpenClaw стало проще работать с доступом и адресатами VK без ручной правки JSON: плагин умеет отдельно обслуживать списки доступа для личных сообщений и групповых бесед, а также отдавать нормализованные VK-идентификаторы для выбора цели.

### Улучшено
- Форматированные ответы в VK теперь обрабатываются заметно полнее: корректно рендерятся заголовки, цитаты, чекбоксы, таблицы и длинные сообщения, которые раньше могли ломаться при разбиении на части.
- Таблицы в ответах агента теперь строятся через актуальную версию `markdown-to-vk`, поэтому выравнивание колонок и форматирование внутри ячеек стало стабильнее.
- Длинные подписи к изображениям, документам и голосовым сообщениям больше не обрезаются на первом сообщении: вложение приходит вместе с началом текста, а продолжение уходит следующими сообщениями без потери контекста ответа.

### Исправлено
- Файлы и медиа по URL без расширения теперь чаще приходят в VK с понятным именем и правильным типом: плагин учитывает query-параметры, `Content-Disposition` и `Content-Type`.
- Относительные `MEDIA:` и другие локальные пути теперь резолвятся от разрешённых workspace roots, а не от случайного рабочего каталога gateway, поэтому отправка локальных файлов после деплоя стала надёжнее.
- Plain-text ответы для VK теперь очищаются от типичных HTML-тегов и ссылок в угловых скобках, чтобы сообщения не выглядели как сырой HTML.

Кому важно:
- Пользователям, которые отправляют в VK длинные markdown-ответы, таблицы, локальные файлы и изображения из workspace, а также ограничивают доступ через `dmPolicy` и `groupPolicy`.

Что проверить после обновления:
1. Перезапустите шлюз и проверьте, что плагин загружен: `openclaw gateway restart`, `openclaw plugins info vk --json`, `openclaw channels status --json --probe`.
2. Отправьте в VK ответ с заголовками, таблицей, чекбоксами, цитатой и fenced code block; убедитесь, что таблица не разваливается, а блок кода не форматируется как обычный текст.
3. Отправьте ответ с локальным файлом и картинкой по markdown-ссылкам, например `[report](./report.pdf)` и `![image](./shot.png)` или через `MEDIA:./...`; убедитесь, что в VK приходят реальные вложения с ожидаемым именем файла.
4. Ответьте на конкретное входящее сообщение длинным текстом с вложением; убедитесь, что reply сохраняется, первая часть приходит вместе с вложением, а хвост текста не теряется.
5. Если используете `dmPolicy` или `groupPolicy`, проверьте доступ из разрешённого и неразрешённого аккаунта в личке и в групповом чате.

## v2026.4.2

### Улучшено
- Ответы с более сложной Markdown-разметкой в VK теперь отображаются стабильнее: корректно обрабатываются вложенные выделения, инлайн-код внутри форматированного текста и ссылки со скобками в URL. (645999f)
- Сообщения с блоками кода стали чище в VK: лишние пустые строки перед fenced code block теперь автоматически убираются. (645999f)

### Исправлено
- Если VK отклоняет отправку изображения по URL (`photo is undefined`), плагин пытается скачать изображение на стороне OpenClaw и повторно загрузить его как вложение.
- Если токену не хватает прав `photos` и/или `docs`, сообщения с вложениями больше не «теряются»: плагин отправляет безопасный текстовый fallback (подпись + исходный URL, либо пояснение для сгенерированных файлов без публичной ссылки).
- При временных ошибках повторная отправка теперь стабильнее и с меньшим риском дублей одного и того же сообщения.

Кому важно:
- Пользователям, у которых агент часто отправляет форматированные ответы (Markdown, кодовые блоки) и медиа-вложения (изображения, документы, голосовые), особенно при нестабильных URL источников или ограниченных правах VK token.

Что проверить после обновления:
1. Перезапустите шлюз и проверьте, что канал активен: `openclaw channels status --json --probe`.
2. Отправьте тестовый ответ с `*курсивом*`, `**жирным**`, инлайн-кодом (`` `code` ``) и ссылкой вида `[docs](https://example.com/path_(v2))`; убедитесь, что форматирование в VK отображается корректно.
3. Отправьте изображение по публичному `https://` URL и проверьте, что оно приходит как вложение, а не только как текстовая ссылка.
4. Если есть стенд с ограниченным токеном (без `photos`/`docs`), проверьте fallback-сценарий: сообщение должно дойти в VK в текстовом виде, без падения отправки.
