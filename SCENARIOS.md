# Пользовательские сценарии

## Пересланное и пост со стены

Действие: в личном диалоге переслать боту чужое сообщение, поделиться постом со стены и ответить цитатой на одно из них.

Результат: агент видит автора, дату (в поясе пользователя), номер, текст и фотографии пересланного, текст и фотографии поста, а в цитате — её текст, автора и дату; команды и упоминание бота определяются только по тексту самого отправителя.

## Чужой контекст в группе

Действие: в группе с `contextVisibility: allowlist` участник из `groupAllowFrom` пересылает сообщение и отвечает цитатой на сообщение автора, которого в списке нет.

Результат: агент получает само сообщение участника, но не видит ни пересылку, ни цитату постороннего автора; если сообщение состояло только из скрытых пересылок, ответа нет, а в журнале gateway есть строка о причине.

## Цитирование ответов

Действие: отправить обычное сообщение боту сначала в личном диалоге, затем в групповой беседе, а после нажать callback-кнопку.

Результат: ответ в личном диалоге приходит без цитаты; ответ в группе цитирует входящее сообщение; ответ на callback сохраняет привязку к сообщению с кнопкой.

## Совместимость с Node.js

Действие: установить VK-плагин в OpenClaw 2026.8.1 на Node.js из поддерживаемого самим OpenClaw диапазона.

Результат: установка допускается на Node.js 22.22.3–22.x, 24.15.0–24.x и 25.9.0+, а неподдерживаемые ветки отклоняются до запуска плагина.

## Обновление до OpenClaw 2026.8.2

Действие: установить `@openclaw-vk/vk@2026.8.31`, перезапустить gateway и выполнить `openclaw channels status --probe`.

Результат: VK-плагин загружается без ошибок SDK, канал работает в режиме Long Poll, probe возвращает `works`.

## Длительная работа Long Poll

Действие: оставить подключённый VK-канал без входящих сообщений более чем на 30 минут.

Результат: успешные пустые Long Poll-ответы обновляют транспортную активность; gateway не считает канал зависшим и не запускает цикл перезапусков.

## Зависший Long Poll

Действие: после хотя бы одного успешного опроса транспорт перестаёт завершать Long Poll-запросы дольше `channels.vk.transport.silenceMs`.

Результат: задача аккаунта завершается, а единственным владельцем повторного запуска остаётся штатный lifecycle OpenClaw.

## Диагностика без утечки данных

Действие: включить `channels.vk.diagnostics.level: "redacted"`, вызвать ошибку доставки и проверить журнал gateway.

Результат: журнал содержит этап, вид вложения и безопасный код ошибки, но не содержит токен, подписанный URL, путь, имя собеседника или содержимое вложения; account-level `diagnostics` отклоняется валидатором.

## Doctor в OpenClaw 2026.9.5

Действие: установить плагин, выполнить `openclaw doctor --fix`, затем проверить `openclaw status`.

Результат: VK-плагин явно сообщает пустой контракт собственных state-миграций и не удерживает gateway в состоянии ожидающей миграции.

## Личное сообщение и ответ

Действие: разрешённый пользователь отправляет боту личное сообщение, агент отвечает текстом.

Результат: входящее сообщение попадает правильному агенту, ответ доставляется в тот же VK-диалог.

## Pairing нового пользователя

Действие: новый пользователь пишет боту при `dmPolicy: "pairing"`, затем оператор подтверждает полученный код.

Результат: доступ открывается только подтверждённому пользователю и только для исходного `accountId`.

## Несколько VK-сообществ

Действие: запросить и подтвердить pairing отдельно в двух именованных VK-аккаунтах.

Результат: подтверждение в одном сообществе не открывает доступ во втором.

## Токен сообщества ссылкой на секрет

Действие: задать `channels.vk.token: { "source": "env", "provider": "default", "id": "VK_GROUP_TOKEN" }` с токеном сообщества в переменной `VK_GROUP_TOKEN` окружения gateway, выполнить `openclaw gateway restart` и написать боту в личные сообщения. Затем задать рядом непустой `channels.vk.tokenFile` и снова перезапустить. Затем убрать `tokenFile`, указать в ссылке переменную, которой в окружении нет (`"id": "VK_MISSING"`), и перезапустить.

Результат: с одной ссылкой бот отвечает, токена в `openclaw.json` нет. С непустым `tokenFile` токен читается из файла, а ссылка не разрешается вовсе и не мешает запуску. Когда ссылку не разрешить, учётная запись VK не стартует, в журнале названа ссылка (`source:provider:id`), остальные каналы работают.

## Входящие вложения

Действие: отправить одним сообщением изображение и документ.

Результат: агент получает оба вложения в исходном порядке с корректными типами и локально материализованными файлами.

## Длинная озвучка ответа

Действие: попросить бота озвучить ответ, речь которого длиннее пяти минут.

Результат: озвучка приходит несколькими голосовыми подряд, разрывы попадают на паузы в речи, вместе они читают весь текст; если проверенную нарезку сделать не удалось, приходит документ, а не обрезанное голосовое.

## Пределы озвучки в конфиге

Действие: задать `channels.vk.audio.maxSegments: 0`, затем перенести блок `audio` внутрь `channels.vk.accounts.<id>` и каждый раз выполнить `openclaw config validate`.

Результат: оба конфига отклоняются до запуска — пределы задаются только на весь канал и только целыми положительными числами.

## Черновик шагов

Действие: задать `channels.vk.streaming: { mode: "progress", progress: { label: "⏳ Работаю", toolProgress: true } }` и попросить агента о задаче с вызовом инструмента — сначала в личном диалоге, затем в групповой беседе.

Результат: в чате одно сообщение с заголовком и строками шагов, которое правится по ходу работы и в конце становится ответом без заголовка; длинный ответ продолжается следующими сообщениями, картинки и голосовые приходят следом; в группе ответ цитирует входящее сообщение, в личке — нет. Ход, закончившийся без ответа, не оставляет сообщения «работаю».

## Черновик шагов и кнопки

Действие: при включённом черновике шагов нажать кнопку меню бота, по которой агент вызывает инструмент и выдаёт ответ блоками с пустым финальным событием.

Результат: весь ответ приходит один раз новым сообщением с цитатой сообщения с кнопкой, клавиатура снимается, черновик удаляется; если новое сообщение не удалось отправить, уже показанный ответ остаётся в черновике без заголовка «работаю».

## Ошибка хвоста длинного ответа

Действие: при включённых статусных реакциях и черновике шагов VK принимает начало длинного ответа, но отправка следующей части завершается ошибкой, которую диспетчер сообщает через `onError`.

Результат: доставленное начало не отправляется повторно, а статусная реакция показывает ошибку вместо успешного завершения.

## Настройка черновика в конфиге

Действие: задать `channels.vk.streaming.mode: "partial"`, затем `channels.vk.streaming: true`, затем перенести блок `streaming` внутрь `channels.vk.accounts.<id>` и каждый раз выполнить `openclaw config validate`.

Результат: все три конфига отклоняются до запуска — VK умеет только режимы `off` и `progress`, и задаются они на весь канал.

## Вопрос агента с вариантами

Действие: в личном диалоге агент задаёт вопрос с вариантами; пользователь нажимает кнопку, в другой раз отвечает текстом «2», в третий пишет «стоп», в четвёртый не отвечает.

Результат: нажатие и текстовый ответ закрывают вопрос, ход продолжается, кнопки снимаются с пометкой «✅ Ответ: …»; текстовый ответ не приходит агенту отдельным сообщением; «стоп» прерывает ход, а не отвечает на вопрос; без ответа кнопки снимаются с пометкой «⌛ Время на ответ вышло».
